# Geometry Rhythm — архитектура и форматы данных

Игра по-прежнему запускается `python main.py`; все модули лежат в `core/` (путь добавляется в `sys.path`
самим `main.py`, как и раньше). Новый код следует тем же правилам, что и старый: размеры — через
`screen_setting` (`SS.U/UR/UP`), тексты — через `i18n.t()` (русские ключи → английский словарь),
цвета/шрифты — из `config` и `style`.

## Слои

| Слой | Модули | Что делает |
|---|---|---|
| Данные и файлы | `jsonio`, `validation`, `chart`, `songs`, `records`, `settings` | атомарная запись, карантин повреждённых файлов, строгая проверка и миграция чартов |
| Логика (без pygame-экранов) | `engine`, `scoring`, `noteindex`, `beatgrid`, `history`, `autosave`, `ghost`, `progress`, `library`, `practice` (конфиг) | чистые вычисления, тестируются без окна |
| Подготовка | `session` | всё тяжёлое делается до старта песни |
| Экраны | `game`, `results`, `results_stats`, `editor`, `songs_screen`, `history_screen`, `startup`, `practice` (экран), `achievements_*` | только ввод и отрисовка |
| Склейка | `runs`, `main` | порядок: практика → заставка → подготовка → игра → результаты |

## Как это работает

**Чарт (v5).** `validation.check_chart` проверяет типы, диапазоны, порядок и границы, возвращает
нормализованный словарь и отчёт (ошибки/предупреждения, RU/EN). Старые версии (1–4) мигрируют; перед
миграцией файла редактор делает резервную копию. Неизвестные верхние поля сохраняются как есть.
Идентификатор `id` стабилен и переживает переименование файла; `grid` — настройки BPM-сетки.

**Запись файлов (`jsonio`).** Пишется временный файл → `fsync` → `os.replace`. Повреждённый файл не затирается,
а переименовывается в `*.corrupt-<время>` (хранится последних 5), и подставляется значение по умолчанию.
Ротируемые бэкапы: `backup_file(path, dir, keep)`.

**Автосохранение (`autosave`).** Редактор пишет оболочку `data/autosave/<ключ>.autosave.json` (3 поколения)
через 20 с после первой несохранённой правки (после «важных» действий — не чаще раза в 3 с), в фоновом потоке.
Оболочка хранит `base_hash` исходного файла. При запуске (`startup.run`) `scan` классифицирует находки:
`newer` (автосохранение новее файла), `conflict` (файл менялся после начала правки → только как новая копия),
`orphan` (чарта уже нет), `draft` (новый несохранённый чарт), `legacy`, `identical` (молча удаляется),
`corrupt`. Пользователь выбирает: восстановить / оставить / удалить / позже. Очистка: старше 30 дней или
больше 60 файлов. Аварийное автосохранение — при выходе из редактора по QUIT и при исключении.
Отключается в настройках («автосохранение»).

**История правок (`history`).** Паттерн «команда»: каждое изменение — объект с `do/undo`, подряд идущие
однотипные (перетаскивание, колесо) склеиваются; лимит 300 команд и 600 000 «стоимости». Метка сохранения
определяет «есть несохранённые изменения» корректно даже после undo/redo.

**BPM-сетка (`beatgrid`).** Время линии = `offset + i·шаг`; хранится BPM/offset/деление/размер такта.
Изменение BPM не двигает существующие ноты; позиции считаются от индекса, поэтому дрейфа float нет.
Привязка (snap) включается/выключается, есть tap-tempo, квантование выделенных нот.

**Подготовка (`session`).** Шаги: проверка чарта → проверка песни → структуры (`NoteIndex`: bisect по времени
начала + бегущий максимум конца) → медиа событий (нет файла → предупреждение, событие пропускается) → звук
(замедление для практики + предзагрузка). Нет песни/нот/чарт невалиден → `PrepError` и экран с причиной.
Во время игры диск не читается и JSON не разбирается.

**Движок (`engine`).** Время — в мс чарта, события наружу идут через `sink`. Точность считает также срыв
удержания: удержание засчитано = 1.0, сорвано = 0.0 как отдельное решение; пропущенная голова = один MISS.
Тики удержания детерминированы (каждые 200 мс от попадания). Практика: HP не уменьшается (или опционально
держится на 1), поражения нет, notes вне участка A–B получают состояние `skip`.

**Единая временная шкала звука (`stretch`, `audio`).** Измерено: `mixer.music.play(start=…)` для WAV отбрасывает
дробную часть секунд (старт с 7.3 с играл с 7.0 с), а потоковое декодирование MP3/OGG стартует на 20–45 мс позже
полного декодирования. Поэтому ВСЕ скорости (включая 1x) играют из PCM-WAV в `data/cache/speed` (файл создаётся при
первом запуске песни, имя содержит отпечаток песни; кэш чистится сверх ~1.5 ГБ), а `audio.play_song` проигрывает
его из памяти срезом сэмплов — позиция точна до сэмпла для любой скорости. Если формат WAV не совпадает с микшером
или нет numpy — резервный путь через `mixer.music` (на 1x). Игра запускает музыку с поправкой на кадр запаздывания.

**События «картинка»/«ролик» → «на весь экран».** Поле `full` (bool, по умолчанию false; старые чарты без него
открываются как раньше). При `full` изображение растягивается точно на размер экрана (`events.media_size`), размер и
смещение/движение игнорируются, плавность появления остаётся.

**Практика (`practice`).** Участок A–B на таймлайне, зацикливание, быстрый рестарт (R), скорости 50/75/90/100,
настройки в `data/practice.json`. Результаты практики не попадают в рекорды, ранги и достижения за
прохождение; у практики свои счётчики и достижения. Замедление — методом «пластинки»
(`stretch.ensure`, высота тона меняется), результат кэшируется.

**Статистика (`scoring`, `results_stats`).** Вкладка «ПОДРОБНО»: среднее/абсолютное/σ отклонения, рано/поздно,
гистограмма, диаграмма рассеяния, динамика по песне, сравнение с личным рекордом.

**Ghost (`ghost`).** `data/ghosts/<ключ>.ghost.json` хранит лучший полный проход обычного режима
(таймлайн очков/комбо). Привязан к `notes_hash` чарта: если ноты изменились — призрак «устарел» и не
показывается. Заменяется только строго лучшим результатом (очки, затем точность). Повреждённый файл уходит
в карантин, файл более новой версии не перезаписывается.

**Достижения (`progress`).** Те же `data/achievements_unlocked.json`, встроенные с префиксом `gr:`. Счётчики —
`data/progress.json` (только растут, начинаются с нуля). Категории: игра, без промахов, комбо, ранги, точность,
сложность, серии, редактор, создание, практика. Минимум 30 нот для «чистых» достижений.

**Избранное и история (`library`, `history_screen`).** `data/library.json`. Песни — по отпечатку файла
(`fp:sha1(начало+конец+размер)`, запасной вариант `name:`), чарты — `id:` или `file:`. История ≤ 200 записей;
запуск без завершения хранится с `result: null`, завершённый — с кратким итогом.

## Форматы файлов в `data/`

| Файл | Версия | Примечание |
|---|---|---|
| `charts/*.json` | chart v5 | `version,id,name,song,difficulty,notes[],events[],grid{}` + неизвестные поля; у image/video события — `full` |
| `cache/speed/*.wav` | — | кэш PCM-дорожек (не нужен при переносе, создаётся сам) |
| `autosave/*.autosave.json` | envelope v1 | см. выше |
| `ghosts/*.ghost.json` | v1 | `notes_hash`, `score`, `acc`, `timeline[[t,score,combo]…]` (≤ 40 000 точек) |
| `library.json` | v1 | `favorites{songs,charts}`, `history[]` |
| `progress.json` | v1 | числовые счётчики + `s_chart_keys`, `created_ids` |
| `practice.json` | v1 | `a,b,speed,loop,hp_loss` |
| `settings.json`, `records`, `wins`, `ranks`, `achievements_unlocked.json` | как было | старые файлы читаются без изменений; новые настройки добавляются со значениями по умолчанию |

## Запуск, тесты, сборка

```
pip install -r requirements.txt        # pygame, numpy, opencv-python
python main.py
pip install -r requirements-dev.txt && python -m pytest tests -q
build_exe.bat                           # Windows: dist\GeometryRhythm.exe + songs, data, images рядом; всё остальное внутри exe
```

Тесты работают без окна и звука (`SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy`), пути данных
изолируются во временную папку (`tests/conftest.py`), настоящие `data/` не затрагиваются.
